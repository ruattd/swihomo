# 状态与故障排查

排查连接问题时，先看「主页」的状态与当前配置文件，再检查「连接」「日志」与「资源」。本页只列出应用实际提供的信息与操作。

## 主页状态

状态卡显示以下四种状态：

| 状态 | 含义 |
| --- | --- |
| 已连接 | 隧道已建立 |
| 连接中 | 正在建立连接；系统重建隧道时也会短暂显示此状态 |
| 断开连接中 | 正在关闭隧道 |
| 未连接 | 当前没有活动连接 |

状态下方显示当前配置文件的名称；没有活动配置文件时显示「选择配置文件以开始」。没有活动配置文件，或状态处于「连接中」「断开连接中」时，连接开关不可用。

## 连接

「连接」页仅在已连接时显示实时连接；未连接时会提示「连接后查看连接」。

- 每一行显示进程名、目标地址、匹配规则以及实时上下行速度，列表每秒刷新。
- 使用搜索框按进程名、域名或 IP 地址筛选；搜索会匹配进程、目标地址、远程目标、目标 IP 与 `ip:port`。
- 可通过工具栏的「排序方式」按进程、实时速度或规则排序，并切换升序或降序。
- 点开任意连接可查看「实时速度」「流量」「路由」与「连接」详情。若流量走向与预期不符，重点检查「规则」「规则内容」与「代理链」。
- 「全部关闭」会立即关闭 mihomo 管理的所有连接，操作前会再次确认。

没有活动连接时页面显示「没有活动连接」，新流量出现后会自动更新。

## 日志

日志有两个来源：「应用」与「核心」。应用日志记录 Swihomo 的生命周期、配置文件、隧道与错误事件；核心日志来自 mihomo，并且只在已连接时更新。每个来源各自保留最新的 1,000 条记录。

- 使用搜索框按模块、消息、来源名称或等级查找。
- 工具栏的筛选菜单可按来源（所有、应用、核心）或等级（所有级别、调试、信息、警告、错误）筛选。
- 「应用日志级别」在偏好中设置；「Mihomo 日志级别」在覆盖设置中设置，选择「静默」后核心不再产生日志。
- 「更多」菜单提供「返回底部」与「清除日志」。「清除日志」可选择清除应用日志、核心日志或所有日志。清除是永久操作，「清除所有日志」会同时移除两个来源的记录。

未连接时清除核心日志，Swihomo 会在下次核心启动时执行该清除操作。

需要复现问题时，可临时把「应用日志级别」与「Mihomo 日志级别」调到「调试」，复现后按模块或消息搜索。应用级错误会同时显示在页面顶部的「请求未完成」横幅中，并记录为应用日志，可对照查看具体错误信息。

## 资源

「资源」页仅在已连接时显示文件，列出当前配置文件的「代理提供程序」「规则提供程序」与「地理数据」。

- 「就绪」表示对应文件存在且不是目录，并不校验内容是否有效；「缺失」表示文件尚未写入。
- 「上次更新」来自核心记录；地理数据还会显示「已缓存到 MihomoCore」或「尚未缓存」。
- 对提供程序点「更新」会重新加载其内容；「编辑」仅支持 UTF-8 文件，「替换」可用其他文件覆盖。
- 「更新」会刷新已启用的地理数据数据库。替换地理数据文件后，需要重新连接才能加载新文件。

如果页面显示「没有资源」，表示当前配置文件没有受管理的提供程序或 GeoIP 和 GeoSite 规则。如果所需资源持续显示「缺失」，可点「更新」重新下载，或使用「替换」选择文件，然后重新连接以让核心加载。

<a id="reconnect"></a>

## 需要重新连接的情况

以下更改不会立即作用于正在运行的隧道：

- 「偏好」→「数据包隧道」中的所有选项。
- 「覆盖设置」中启用 DNS、外部控制器开关、控制器端口、控制器密钥与自定义 YAML 的更改。其他基本设置会实时生效。
- 「实验性」中「用规则集替代 Geo 数据库」与「自动回收内存」在下次连接时生效。
- 配置文件的「覆盖设置...」中的更改在该配置文件下次连接时加载。

保存覆盖设置时，如果当前已连接且更改需要重连，应用会显示「重新连接以应用更改？」对话框，点「重新连接」即可应用。切换到其他配置文件时无需手动重连，Swihomo 会自动完成切换。

<a id="geo-memory"></a>

## 内存与 Geo 数据库

移动设备上，系统对 Network Extension 的内存限制约为 50–70 MB，超限会终止扩展进程。Geo 数据库在启动时通常占用 30 MB 以上，并可能继续增长。因此，如果隧道意外断开或无法启动，而配置依赖 Geo 数据库，内存占用是值得优先检查的原因之一。

可尝试以下减负方式：

- 在「偏好」→「实验性」中开启「用规则集替代 Geo 数据库」。该选项会把 `GEOIP`/`GEOSITE` 规则与 DNS 中的 geosite 策略改写为 mrs 规则集，并移除 Geo 数据库设置，但不会迁移 `dns.fallback-filter.geosite`。改写会在下次连接时生效。
- 在「偏好」→「数据包隧道」中把「网络栈」设为 mipstack，它比 gVisor 更轻量，可以减少内存占用。
- 开启「自动回收内存」，让 mihomo 在内存压力过高时释放未使用的内存。

这些选项不能保证解决所有断连问题，但可以在配置包含大量 Geo 规则时降低内存压力。

## 安全排查清单

1. 查看「主页」状态卡与下方的配置文件名称，确认连接的是预期配置。
2. 关闭再开启连接，以重新应用需要重连的设置。
3. 将日志级别调到「调试」，复现问题后按来源、等级、模块或消息筛选日志。
4. 在「连接」中搜索相关进程或目标地址，打开详情检查「规则」与「代理链」。
5. 在「资源」中确认所需文件显示「就绪」，并检查「上次更新」；替换地理数据文件后重新连接。
6. 结合顶部「请求未完成」横幅与应用日志中的对应记录，确认具体错误信息。
7. 如果配置包含大量 Geo 规则且出现断连，参考上文调整内存相关选项。

「工具」页目前只有「iCloud 同步」可用；「测速」「Ping」与「DNS 查询」仍显示「敬请期待」，不能作为诊断依据。
