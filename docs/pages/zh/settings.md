# 设置

Swihomo 的设置分为两部分：「偏好」保存此设备的应用行为，「覆盖设置」决定连接时如何生成 mihomo 配置。此外，「iCloud 同步」可在设备之间同步部分数据。

<a id="preferences"></a>

## 偏好

### 外观

「浅色」「深色」与「系统」立即生效；选择「系统」时跟随设备外观。

### 菜单栏（仅 macOS）

- **在菜单栏显示 Swihomo**：启用菜单栏入口。
- **显示**：仅图标、仅速度或图标 + 速度。「仅图标」时，菜单栏显示实时传输速度而非累计流量。
- **隐藏 Dock 图标**：需先启用菜单栏显示。

### 应用程序

- **应用日志级别**：调试、信息、警告或错误，仅控制 Swihomo 应用日志。mihomo 核心日志请在覆盖设置中调整。
- **语言**：系统默认、English 或简体中文。
- **自动折叠其他代理组**：展开一个代理组时，自动折叠其他已展开的代理组。
- **显示订阅信息**：隐藏、已使用或剩余，控制配置文件与提供程序上显示的订阅用量。

<a id="packet-tunnel"></a>

### 数据包隧道

::: warning 注意
以下所有设置将在重新连接后生效。
:::

- **MTU**：1280 到 4064 之间，默认 1500。错误的 MTU 可能导致连接或网络问题。
- **通过隧道传输 IPv6**：默认开启。关闭后，IPv6 流量可能绕过 mihomo。
- **网络栈**：mipstack（默认）或 gVisor。mipstack 更轻量，可以减少内存占用。
- **拥塞控制算法**：仅在使用 mipstack 时显示，可选 Cubic（默认）、Reno、BBR 或 BBRv3。BBR 在高延迟或丢包链路上通常表现更好。
- **自定义 DNS 服务器**：每行一个 IPv4 或 IPv6 解析器。该列表独立于覆盖设置中的 DNS 开关。
- **包含所有网络**：默认关闭。开启后，所有网络流量都会纳入数据包隧道，并显示「绕过蜂窝服务」「绕过本地网络」与「绕过 APNs」三个开关。
- **绕过 IP 范围**：每行一个 IPv4 或 IPv6 CIDR，例如 `192.168.1.0/24` 或 `2001:db8::/32`。

这些选项只会在隧道启动时读取，因此修改后需要重新连接。

<a id="experimental"></a>

### 实验性

- **自动回收内存**：默认关闭。内存压力过高时请求 mihomo 释放未使用的内存，下次连接时生效；可能增加垃圾回收频率与耗电。
- **用规则集替代 Geo 数据库**：默认关闭。将 `GEOIP`/`GEOSITE` 规则与 DNS 中的 geosite 策略改写为 mrs 规则集并移除 Geo 数据库设置，减少内存占用；`dns.fallback-filter.geosite` 不会被迁移。此选项在下次连接时生效，内存问题详见[状态与故障排查](/zh/troubleshooting#geo-memory)。
- **实时延迟测试**：默认关闭。关闭时使用代理组 API 的延迟结果，测试失败的节点会显示为错误；开启后会立即影响「代理」页的延迟显示。
- **延迟测试并发数量**：1 到 32，默认 4，仅在「实时延迟测试」开启时可调。

<a id="overrides"></a>

## 覆盖设置

覆盖设置对每个配置文件生效，分为基本设置、外部控制器与自定义 YAML 覆盖。

### 基本设置

基本设置应用于自定义 YAML 之后，因此这些值始终优先：

- **路由模式**：规则（默认）、全局或直连。
- **Mihomo 日志级别**：调试、信息（默认）、警告、错误或静默。
- **允许 LAN 连接**与**启用 IPv6** 默认关闭；**启用 DNS** 默认开启。
- **混合端口**：1 到 65535，默认 7890。

除「启用 DNS」外，基本设置保存后会实时更新到运行中的核心；「启用 DNS」的更改需要重新连接。

### 外部控制器

- **启用外部控制器**：默认关闭。开启后在 `127.0.0.1` 上为第三方客户端暴露 mihomo REST API。Swihomo 自身直接与核心通信，关闭此项不受影响。
- **控制器端口**：1 到 65535，默认 9090。
- **控制器密钥**：首次运行时自动生成，可切换显示。

端口与密钥仅在外部控制器开启后可用。

### 自定义 YAML 覆盖

自定义 YAML 会深度合并到每个配置文件的字段中，而不修改原始订阅。语法与配置文件覆盖一致：

- `key!`：替换现有对象
- `+key` 或 `key+`：在数组前插入或向后追加数组项
- `<key>`：转义以 `+` 开头或结尾的字面量键

完整说明见 [Mihomo Party 覆盖参考](https://clashparty.org/docs/guide/override/yaml)。

### 保存与生效

页面底部会显示「所有更改已保存」或「有未保存的更改」。基础设置会实时更新，DNS、外部控制器和 YAML 的更改在重新连接后生效。

已连接时保存需要重新连接的更改，会弹出「重新连接以应用更改？」对话框，可选择「重新连接」立即应用，或选择「暂不」稍后手动重连。

### 与配置文件覆盖的关系

全局覆盖设置对所有配置文件生效。每个配置文件还可以通过卡片菜单的「覆盖设置...」设置自己的覆盖，并可关闭「启用全局覆盖」以忽略全局自定义 YAML。连接时的合并顺序如下：

1. 配置文件 YAML
2. 全局自定义 YAML（若此配置文件的「启用全局覆盖」开启）
3. 配置文件自定义 YAML
4. 应用生成的标准覆盖（基本设置始终优先）
5. 可选的 Geo 数据库到规则集改写

详见[配置与订阅](/zh/profiles#profile-overrides)。

<a id="icloud-sync"></a>

## iCloud 同步

在「工具」中打开「iCloud 同步」。主开关开启后，只有对应分类的开关也开启时才会同步该分类；关闭分类开关不会删除 iCloud 中已有的数据。

- **同步状态**与**立即同步**：显示最近一次同步事件；尚未同步时显示「暂无同步记录」，主开关关闭时「立即同步」不可用。
- **偏好设置**：通用偏好、排序偏好、Packet Tunnel 配置与 Experimental 配置。
- **配置文件**：配置文件列表（含内容、订阅 URL 与配置文件覆盖）与全局覆盖设置。配置文件内容会原样同步，包括 YAML 中可能存在的密钥。
- **危险操作**：删除 iCloud 数据会移除 Swihomo 存储在 iCloud 中的全部内容，不影响本机数据。

以下数据始终只保存在当前设备，不会随 iCloud 同步：

- 当前活动配置文件的选择
- 控制器密钥

如果 iCloud 中已有同步设置，开启同步时会询问使用「云端覆盖本机」还是「本机覆盖云端」。

## 需要重新连接的更改

有些设置只在隧道启动时读取：

- [数据包隧道](/zh/settings#packet-tunnel)中的所有选项。
- [覆盖设置](/zh/settings#overrides)中的「启用 DNS」、外部控制器及其端口或密钥，以及自定义 YAML。
- [实验性](/zh/settings#experimental)中的「用规则集替代 Geo 数据库」与「自动回收内存」，它们在下次连接时生效。
- 配置文件的[自定义覆盖](/zh/profiles#profile-overrides)，会在该配置文件下次连接时加载。

要应用这些更改，可从「主页」断开再连接，或在「覆盖设置」中保存后选择「重新连接以应用更改？」中的「重新连接」。已连接时切换到其他配置文件也会自动重连。
