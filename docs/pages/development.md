# Development Setup

This guide gets Swihomo building on a local Mac. The project has two Xcode targets: the SwiftUI app and a Packet Tunnel extension linked to a locally built mihomo core.

For a tour of the source tree, see [Project Structure](/project-structure). For the contribution workflow, see [Contributing](/contributing).

## Requirements

- An Apple silicon Mac. The current core build and Xcode project target arm64.
- Xcode 26 or newer with its command-line tools.
- Go 1.26.8 available on `PATH`.
- Git with submodule support.
- An Apple Developer team that can sign the app and Packet Tunnel extension with the required Network Extension entitlement.

The deployment targets are iOS 17.0 and macOS 14.0. Use a signed macOS host or a physical iOS device when testing the tunnel; the Simulator cannot run a Packet Tunnel.

## Get the source

```sh
git clone --recurse-submodules https://github.com/ruattd/swihomo.git
cd swihomo
```

If you already cloned without submodules, initialize and verify them with:

```sh
bash scripts/init-submodules.sh
```

A successful run leaves `Vendor/mihomo` at the commit recorded by the project.

## Build the mihomo core

```sh
bash scripts/build-mihomo.sh
```

The script builds the bridge for iOS, iOS Simulator, and macOS, then assembles `Vendor/MihomoCore.xcframework`. The PacketTunnel target also runs this script from its **Build mihomo** phase when the core inputs change, so you normally do not need to repeat it before every Xcode build.

## Open and run

```sh
open Swihomo.xcodeproj
```

1. Select your development team for both the `Swihomo` and `PacketTunnel` targets.
2. Change both bundle identifiers to values registered to your team. The defaults are `com.swihomo.client` and `com.swihomo.client.PacketTunnel`.
3. Build the shared `Swihomo` scheme and run it on a signed macOS host or a physical iOS device.

Xcode resolves the pinned Swift package dependencies automatically on the first build.

> [!IMPORTANT]
> The iOS Simulator cannot run a Packet Tunnel. Do not use it to verify connection behavior.

## Generated files

- `Vendor/MihomoCore.xcframework/` is generated by `scripts/build-mihomo.sh` and ignored by Git.
- `Vendor/mihomo/.build-mihomo/` contains intermediate build products and is ignored by Git.
- `Swihomo/Shared/MihomoCoreVersion.swift` is generated by `scripts/export-mihomo-version.sh`. It is tracked but should not be edited by hand. A normal Xcode build does not regenerate it.

Do not commit the XCFramework, intermediate build products, signing material, or local environment files.

## Updating the core

When your change updates the core submodule, rebuild it and regenerate the version file:

```sh
git submodule update --remote --merge Vendor/mihomo
bash scripts/build-mihomo.sh
bash scripts/export-mihomo-version.sh
```

Commit the submodule pointer and the regenerated `Swihomo/Shared/MihomoCoreVersion.swift` together. The version file keeps the default `ClashMeta/<version>` subscription User-Agent aligned with the embedded core.

## Work on the documentation

The documentation is an independent pnpm/VitePress project and does not require Xcode:

```sh
pnpm --dir docs install
pnpm --dir docs dev
```

Before submitting documentation changes, check the production build:

```sh
pnpm --dir docs build
```

If you change documentation dependencies, include the updated `docs/pnpm-lock.yaml` in the same change.
